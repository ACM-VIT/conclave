## R3 (B6-T3, information only): the attendee hand capability and the Q&A badge need no CallControlsPresenter edit

The task note planned "the attendee hand capability in CallControlsPresenter (B6-T3's) is a request". It turned out to
need no change in B6-T3's files:

- The view model now passes `isWebinarQaEnabled`, `webinarQaUnseen` (the one derived R18 counter) and
  `attendeeCanRaiseHand` into `CallControlsInputs.fromShell(...)` (`makeCallControlsInputs()`), which
  `ControlBarPolicy` already reads (attendee Raise Hand shown only with the capability, Q&A badge).
- S1 now has `MeetingShellInputs.attendeeCanRaiseHand`: with it the attendee's hand row is visible and follows the
  call, so `CallControlsPresenter.tap(.hand)` -> `shell.toggleHand()` dispatches, and the view model routes an
  attendee's hand to `webinar:setHandRaised` (S20 Q10) under the same F7 token.
- If B6-T3 publishes More's attention dot (`moreAttention`) from the VM, pass it in `makeCallControlsInputs()` in the
  parameter order of `CallControlsInputs.fromShell` (after `attendeeCanRaiseHand`, before `isRoomLocked`).
