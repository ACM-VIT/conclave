# Native icon inputs

Build-time only, offline, finite WP1 selection. From the repository root:

- `pnpm run check:native-icons`: read-only drift check; fails on missing, stale or extra outputs and never writes.
- `pnpm run generate:native-icons`: validates every input first, stages all outputs, then replaces only its enumerated files.
- `pnpm run test:native-icons`: converter semantics, independent geometry, archived-semantics replay, fail-closed validation and drift.

The generator uses the Python standard library only and never fetches inputs.

Material Symbols by Google, from commit `49d4db35df873165d6bd6ba09b063c7dafbac2f4`. Original SVGs and the complete Apache 2.0 license (including appendix) remain unmodified in `vendor/material-symbols`. Acquisition records explicitly distinguish five historical digest matches from 49 fresh pinned acquisitions. Fresh metadata preserves duplicate row identities and font-codepoint differences; it does not claim to be the historical snapshot or the metadata that produced that SVG commit. Raw evidence is retained for offline provenance, never bundled or parsed at runtime. Historical paths inside documentary evidence are not build dependencies.

`manifest.json` (schema 3) retains all 36 concepts, 58 contextual Android bindings, 54 variants, 50 exact SF literals and the accepted decisions D01 to D10. Per-binding fill basis, decision, spec references and accessibility (label, value, role) come from the three sealed archived construction records in `semantics-evidence/`. The generator checks their bytes and never parses them; the tests replay them as an independent oracle for the manifest. Labels and values are documentation for localized owners, never ImageVector or Image content. Route invokers, badges, menu actions and switch rows keep their separate semantics. SF artwork remains system-provided, not Google-licensed art.


The hash-linked `additions/polish-20261029/manifest.json` extends the catalog without editing the original arrays, D01-D10 decisions, 5/49 acquisition history, or sealed vendor/semantics evidence. It adds 70 request-backed canonical concepts and seven explicit aliases, 61 newly fetched SVG variants and 66 new SF literals: totals are 106 concepts, 134 bindings, 115 variants and 116 SF literals. Concepts may deliberately share one artwork; no duplicate vectors are generated. Optional labelled whiteboard/browser/Q&A and transport controls can remain text-only. The complete per-concept request mapping is in the extension manifest; original request records are preserved under its `evidence` directory.

Every added SVG is an unmodified official file from the **same commit above**. The offline validator checks the closed manifest, complete file/hash inventory, derived official source URL, HTTP 200/no redirect, raw size/digest, family/fill/24px path and the original sealed axis evidence. Added history says 61 fresh pinned acquisitions and zero historical matches. The original package's strict counts and provenance pins remain mandatory before the extension is read. The complete original Apache license continues to be packaged unchanged.

One upstream file, `auto_awesome.fill0`, has a 24 by 24 implicit viewport rather than the font's 960-unit viewport. Its exact raw SHA-256 is separately pinned in the generator. Only that identity uses rational scaling by 40 after parsing; every other source retains the original `(0,+960)` translation. The strict original parser default still rejects implicit viewports. The generated report records each coordinate profile and binary32 rounding bound; tests independently check this path's coordinates. This is conversion evidence, not native pixel acceptance.

SF availability is checked offline against a preserved Apple CoreGlyphs `name_availability.plist` and its exact projection. Every added name is cataloged for iOS 17.0 or earlier. The requested `xmark.bubble` is absent: `dismiss_question` explicitly uses the iOS 13 `xmark.circle` fallback. USB/hearing-aid counterparts and the Android drag handle's optional iOS counterpart are recorded in P03. Availability metadata does not prove physical-device rendering.

The original Back and Send auto-mirror; the additive Reply and Backspace also mirror. Callers must not flip those vectors again. Vertical Expand is nonmirroring and rotates 180 degrees only when expanded. Conversion uses exact rational decimal arithmetic through relative expansion and the (0,+960) translation, then finite IEEE 754 binary32 literals. `generated-report.json` records the maximum rounding error per asset. One NonZero compound path preserves contours and holes. No runtime parser, eager vector inventory, prewarming or production migration.

Brand input: `brand/conclave-mark.svg` is a byte-identical copy of `apps/web/public/favicon.svg` (SHA-256 pinned in the generator): today's mark, a coral `#F95F4A` rounded diamond with the "acm" letters knocked out by one evenodd path on a 400 unit canvas. The first subpath is the diamond, the other four are the letters. Path text is copied verbatim into the outputs, which place it with group transforms.

App-module drawables (S70 SX8, S20 SC20, S70 11 d) in `apps/conclave-skip/Android/app/src/main/res/drawable`, legal resource names only, resolved by name from the Skip library module: `conclave_mic_fill1`, `conclave_mic_off_fill1`, `conclave_call_end_fill1` and `conclave_cancel_presentation_fill1` (24 dp white single paths with the same binary32 geometry as the matching ImageVectors); `conclave_ic_stat` (24 dp white letterless diamond in the 20 dp live area); `ic_launcher_foreground` (the coral mark scaled to 66 dp and centred in the 108 dp canvas) and `ic_launcher_monochrome` (the same single knockout path in white). That folder is shared with hand-written resources, so the drift check treats only files carrying the generator header as its outputs.

Darwin brand assets (S70 SX9, 11 c), each folder owned whole by the generator (a stale or stray file fails the drift check): `apps/conclave-skip/Darwin/AppIcon.icon` (the Icon Composer document `icon.json` with solid fills only, glass, shadow and translucency off, and the letters layer hidden in the mono appearances, plus its two layer SVGs carrying the brand path verbatim at today's 860 px placement on the 1024 px canvas) and `apps/conclave-skip/Darwin/Assets.xcassets/CallKitIcon.imageset` (the letterless diamond as a 40 pt template vector, which actool renders at 1x, 2x and 3x). The icon tile and the letters take the launcher tile color from the generated `values/colors.xml` (`ic_launcher_background`, written by `gen-native-tokens.mjs`), so regenerate the tokens before the icons when the stage token changes. Xcode renders the iOS 17 to 25 icon images from the document and ignores an `AppIcon.appiconset` of the same name.

No wordmark is generated: the mark is the "acm" lettering, not a "Conclave" wordmark, so S10 R2 keeps its plain title fallback until owner-approved outlined lettering exists.

Hand-owned third-party art (not generated): Google's official sign-in "G" (`GoogleGMark.imageset` at 20 pt and `drawable-*dpi/google_g_mark.png` at 20 dp), recovered unmodified from Google's signin-assets.zip; the asset tests pin each file's SHA-256. Never recolor it: Android draws it with `Image` (never `Icon`, which tints), and the Darwin set uses the original rendering intent (never `.renderingMode(.template)`).

Outputs: `ConclaveIcons.kt`, `NativeIconCatalog.kt` and `NativeConvertedIconFixtures.kt` in `apps/conclave-skip/Sources/Conclave/Skip/ui/icons`; `ConclaveSymbols.swift` and `NativeSymbolCatalog.swift` in `apps/conclave-skip/Sources/Conclave/DesignSystem/iOS/Icons`; the full license as `MaterialSymbols-LICENSE.txt` in the iOS module resources (which Skip also maps into the Android module assets) and in the Android app assets. Final archive inspection and native pixel/runtime acceptance remain separate gates.
